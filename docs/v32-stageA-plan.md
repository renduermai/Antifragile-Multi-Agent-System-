## 核查结果

项目使用 FastAPI、SQLite、LangGraph、Pydantic 和原生前端。现有 30 项测试全部通过，本次耗时 28.63 秒。测试使用隔离数据目录与模拟接口，覆盖跨日记忆、引用校验、概率锁定、期权数学、案例未来信息隔离、任务恢复、预算和备份恢复。测试通过说明已有测试覆盖的行为成立，真实账户权限和最终产品闭环需要另行验收。

六个数据库全部通过 integrity_check 和 foreign_key_check。正式库保存 18 个事件、18 条证据、18 条事件版本、12 条成交快照、1,092 条日线、5 次研究运行、9 份报告和 2 份概率快照。报告中 2 份为 analyzed，7 份为 blocked。期权决策记录为 0。三个案例档案存在，案例输入、验证材料、预测和评分记录均为 0。

已核对项目 docs、work、附件目录中的 TXT、Markdown 及可找到的播客字幕或文档文件。可定位的相关材料为 V3.1、V3.2 需求文件，未找到三案原始案例 TXT、验证 TXT、播客逐字稿、历史网页归档或真实期权报价。其他聊天记录与未提供文件的内容尚无法确认。V3.2 内的 NVDA 新闻、价格及 Ask 保留“用户提供测试设定”身份，后续独立核验。

备份位于项目同级的 ../backups/v32-stageA-20261124-195807，包含五个业务数据库、LangGraph 检查点及 SHA-256 清单。工具校验各库完整性。密钥仍由本地 secrets.json 单独管理，数据库快照不含密钥。后续每次迁移前重新建立当时的快照。

| Provider | options 槽位当前绑定 Massive | 增加独立 MarketData 配置、启停、能力探测、缓存和积分账本，保留 Massive 原配置 |
| 案例 | 显式历史分轮、锁定预测、验证分库、独立评分 | 资料准备、一键后台多轮推进、失败续跑、最终自动评分 |
| 页面 | 三功能区、研究报告、复用部分渲染函数 | 中文结论优先、纵向研究时间线、统一现实与历史展示、折叠管理与技术详情 |
| 调度预算 | 默认关闭、每日 LLM/接口次数限制、缓存、去重任务 | 新增以积分计量的 MarketData 预算，保留现有 LLM 与搜索上限 |

需要优先解决的边界如下。

1. options.py 与 expectations.py 直接请求 Massive /v3 路径并读取专用嵌套字段，不能只更换 Base URL。报价及合约核验、IV 分析均要经过统一适配接口。
2. 当前期权规则只接受 14—75 天到期，研究价格情景默认从 30 天后开始。NVDA 的 11 月 23、25、27 日到期合约会被排除。事件时间窗及短期期权适用性须按可配置、带版本的策略表达，历史规则及记录继续保留。历史回放需按美东交易日和真实开闭市时点判断。
3. 当前报价研究时效上限为 24 小时，对至少延迟 24 小时的试用数据很可能无法计算参考赔率。需要明确区分参考计算资格和当前执行资格，旧报价保留参考价值，执行检查继续采用实际时间、权限与流动性条件。
4. Tavily 结果保存为 search_result，L2 当前要求独立 news_article 来源。需要在合法可访问范围内获取正文并核验来源、独立性及时间；搜索摘要保留线索身份。网页回放增加内容版本和历史可见性检查。
5. 现有“复核期权”只对保存报告执行期权复核。新核心按钮需要持久化串起补充检索、读取旧档案、更新独立判断、锁定概率、获取有界报价和决策，前端显示实际完成步骤。
6. 案例与现实已经共享研究推理和部分数学函数，但案例另有 option_review 分级流程，尚未共用完整检索与决策路径。先通过适配层统一，再接历史自动推进。
7. 当前前端直接显示英文原标题、部分 JSON、内部编号与技术字段。中文展示应有独立缓存与来源映射；翻译失败时给出中文缺口提示，保留可展开原文。模型文本以安全文本或受控渲染展示。

## 官方资料核对

已核对 MarketData 官方期权链、合约报价、到期日、免费账户及限流说明。Base URL 为 https://api.marketdata.app/v1，后续路径使用 /options/...，时间戳按官方字段语义解析。链与单合约响应为并行数组，需要校验长度、空值和 s 状态。单合约支持 date 或 from/to 的历史日终查询；历史数据不保存 IV 和 Greeks。免费及试用数据至少延迟 24 小时、历史限最近一年，actual updated 决定每条报价的实际时点。

积分与请求次数分别记录。不同数据模式的官方计费不同，响应中的限流与消耗信息需在账户实测后核对。默认每日积分预算拟为 80，10,000 积分及 2026-12-24 到期属于用户提供的当前试用状态。无法取得真实余额时展示估算。真实 Token 由用户在灵石区填写后再进行最小范围的联网验收。

官方来源包括 [期权链](https://www.marketdata.app/docs/api/options/chain/)、[合约报价](https://www.marketdata.app/docs/api/options/quotes/)、[到期日](https://www.marketdata.app/docs/api/options/expirations/)、[免费账户](https://www.marketdata.app/docs/account/free-accounts/)及[限流](https://www.marketdata.app/docs/api/rate-limiting/)。

## B—F 开发顺序与交付条件

### B 接入 MarketData

修改 providers.py、main.py、db.py、灵石区渲染及对应测试，增设小范围 MarketData 适配模块。新增独立配置、启停、能力记录、规范化合约及报价缓存、积分预留和实际消耗对账。请求前按有界查询预留预算，并在并发和失败时保留一致账本。未知乘数或非标准交割不自动假定可交易。

交付到期日、过滤链、单合约、历史日期及区间查询。真实测试先用少量合约，核对 updated、延迟、历史范围、权限及官方可取得的额度字段。推荐 GPT-6.1-sol 高思考强度。隔离测试无需外部 API，真实验收目标 3—6 次有界请求，实际积分按模式和响应核算，研究 LLM 预计 0 次。

### C 接入共同赔率和搜索降级

修改 options.py、expectations.py、case_forecast.py 与检索适配层。把标准化数据送入共同数学和分级函数，提供延迟或历史参考赔率、最高可接受权利金、费用及延迟压力情景，保留执行检查。概率在接触报价门槛前锁定。每次研究先选 2—3 个相关到期日和有限执行价，查询失败或数据过旧时尝试已有搜索 Provider。

网页报价需核对完整合约、价格类型、时间及来源。15:55 截断无法取得当时盘中记录时，保留缺口。同日 EOD 报价不进入收盘前预测。推荐 GPT-6.1-sol 高思考强度，重点审查时间和财务计算。真实集成验收目标 1—3 次 LLM、2—4 次搜索，Token 随材料和报告长度变化；行情优先复用缓存。

### D 重构机会猎场

修改 index.html、style.css、research.js、scans.js、options.js、中文展示缓存及后台任务入口。首页提供开始扫描、定向研究和更新机会。详情按一句话结论、新闻变化、因果判断、三类情景、成本判断及后续跟踪排列。核心按钮无需再次填标的，服务端读取事件和报告版本。任务可刷新查询、重入去重、中断恢复。

推荐 GPT-6.1-sol 高思考强度。界面与模拟响应验收不产生外部 API 费用，最小真实中文研究目标 1—3 次 LLM。已有报告可先用于前端验收。

### E 准备案例及自动回放

为黄金、原油、NVDA 分别保存案例输入、验证及来源清单，分清真实来源、用户设定和无法核验项。黄金至少五阶段、原油至少五阶段、NVDA 四轮。自动回放复用共同引擎，以参数化历史时钟运行，逐轮锁定后推进，全部预测完成后独立评分。预算或资料缺失时暂停并保存进度。

阶段开始先检查可取得资料，再开展有明确边界的历史搜索。黄金 2025 年 9 月报价超出一年覆盖，NVDA 周五 15:55 需真实盘中档案，三案均需核实具体来源和实际结果。允许用明确标为用户设定的资料检验推理与数学，但评分不得将它们升级为已核实历史事实。当前模型自身可能知道结局的风险需要在回放说明中呈现。

推荐 GPT-6.1-sol 高思考强度，资料冲突与时间审计可选更强模型作单次复核。按最低轮数估算完整三案约 14 次研究 LLM，失败、额外阶段或核验会增加用量。先运行单轮并检查实际 Token，再决定当日可继续的轮数。评分优先复用确定性审计，搜索预算按阶段单独报告。

### F 统一验收

复用纵向时间线渲染组件和共同研究决策入口，执行旧功能回归及新增集成测试。重点验收 Provider 失败降级、积分并发与缓存、延迟报价禁止当前 L3、EOD 与未来材料隔离、历史自动续跑、旧记录保留及前端自然中文。真实验收基于已缓存资料、少量报价和单个案例，完整三案按预算运行并明确完成状态。

推荐 GPT-6.1-sol 高思考强度。隔离测试和已有数据展示无需外部调用；新增真实研究目标 1—3 次 LLM，只有出现新缺口才扩大验证。

所有调用量为计划范围，受实际接口计费、上下文、失败与模型输出影响。每阶段开始时重新报告预计调用及 Token 量级，完成时报告实际消耗与未验收项。
