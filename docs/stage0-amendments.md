# 阶段 0 确认与补充设计

本文件与原始 V3.1 需求及聊天中的阶段 0 完整方案共同构成实施基线。用户已授权阶段 1。

1. 12 个标的仅为重点行情池。新闻 Provider 可不带股票代码采集，独立搜索 API 单独配置。重大事件反向发现池外资产，保留覆盖缺口。
2. 商品现货、期货、ETF、ETF 期权分别使用品种标识、单位、币种、合约和数据源。代理映射保留基差及展期解释，不混算收益率。
3. 新闻为 Alpaca，行情为 Alpaca，期权为 Massive。新增独立搜索适配 Brave。实际权限、延迟、历史窗口、费用按实测记录，尚未测试的能力标为未知。
4. 首版标准单腿多头 Call/Put，合约规格校验后才计算可执行候选。
5. 手动优先，调度默认关闭。每日 LLM 20 次、每轮深度候选 3 个，可在灵石区调整。调用预算与 Token、费用分别记录。
6. 证据原文或允许摘要、来源、事件/首次公开/版本公开/获取时间持久化。历史判断、未解决矛盾和状态变更追加版本。Checkpoint 用于中断恢复，事件仓储承载跨天记忆。
7. 案例输入、验证材料、预测结果使用独立表，验证材料独立数据库。历史运行只读取确认的证据清单。阶段 5 实施分轮、锁定与访问边界测试。
8. 前端仅保留机会猎场、案例区、灵石区。
9. Fixture 仅运行于隔离测试目录，统一 TEST 标记，生产缺数据时输出具体阻断状态。
10. 保留 A0–A12、吸引子、控制论、捕蝇草独立证据积累、相对错价、反脆弱、新闻冲突、权力结构、极端情景及概率锁定后的赔率反推。

阶段 1 仅实现工程骨架、数据库首版迁移、基础 API、三页、Provider 连接探针及配置状态。复杂采集、LangGraph、期权计算、案例运行和定时执行按原定阶段交付。
